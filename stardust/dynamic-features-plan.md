# Dynamic features — migration plan (NAB home)

Companion to `stardust/dynamic-features.md`. One section per row that needs work
before the archetype is delivered. Rows D6 and D8 need no work.

Target platform: AEM Edge Delivery Services. Target origin not yet known — every
host-bound item below is written against `{branch}--stardust-test--jazhou-adobe.aem.page`
and must be re-pointed at rollout.

---

## D1 — Login selector (DONE — lifted to EDS)

Implemented in the prototype as the observed class toggle, now living in
`blocks/header/header.js` (`wireLoginSelect`). The behavior is identical:
`show-main-login` on the wrapper, `aria-expanded` on the button.
Panel contents are lazy on live and were **not** captured — none were invented.

**Note discovered during the lift:** D1 is **mobile-only**. `motion/index.json`
recorded the handler on `.login-select`, and only `mobile.css` displays that
element; `.login-select-desktop` has no captured behavior. The behavioural gate
therefore exercises D1 at 360, not 1440.

**Verified:** `stardust/scripts/deploy/dynamic-check.mjs` asserts the class flip
and `aria-expanded` tracking at 360. Pixel gate re-run after the change: 0.00%
against the approved prototype at both widths.

## D2 — Mega menu → `header` block (DONE)

The panel markup and promo CTAs come from the captured hidden surface
(`stardust/replica/capture/hidden-surface.json`, regenerated by `gen-hidden.mjs`).

1. The 5 top-level anchors + their panels are authored in `content/nav.html`
   and slotted as nodes — the authored anchor is *moved*, never rebuilt.
2. `wireMegaMenu()` in `blocks/header/header.js` wires open/close on click and
   Escape, `aria-expanded` on each anchor, and a focus trap while open.
3. Panels stay in the DOM and hidden, which is what keeps the content-diff
   inventory matching and what produced the 🟠 EXTRA rows (register R5).

**Verified:** `editability-check.mjs` — 0 lost, 0 duplicated. `dynamic-check.mjs`
asserts 5 anchors, 5 panels, open/close/Escape and `aria-expanded`. Pixel gate
0.00% at both widths.

**Advisory delta:** the *open*-state CSS was never captured (live lazy-loads the
panel styles), so the open panel's presentation is a minimal reconstruction. It
is invisible to the gate, which measures the closed default state.

## D3 — Search overlay → platform search

Do not port NAB's search. Bind the header search button to the EDS search index.

1. Keep the button's captured geometry and icon (it is counted by
   `chrome-parity` — 3 icons at 1440, 2 at 360).
2. Overlay is injected on demand, so it costs no static pixels.
3. Index provisioning happens at rollout, not here.

**Verify:** `chrome-parity` still exit 0 with the button unchanged; search
returns results from the EDS index against a real query.

## D4 — Masthead

Ship as gated: one authored slide. If rotation is wanted, promote to a carousel
block fed from a content sheet — but note this **breaks the pixel gate's
determinism**: band 0–500 is already the only hot band at both widths
(residual R1). Pin a single slide for any future gate run.

**Verify:** if carousel is added, re-run the gate with the carousel locked to
slide 1 (Swiper-lock, per the recreation procedure's interaction-parity rules).

## D5 — Footer accordions → `footer` block, mobile only (DONE)

Nothing fired at 1440 because the panels render expanded at desktop. At 360 the
collapsed state is a layout fact, not a behavior — the gated CSS already
produces it.

1. `wireAccordion()` in `blocks/footer/footer.js` adds expand/collapse +
   `aria-expanded` **only** under `matchMedia('(max-width: 767px)')`.
2. No transitions — none were observed.
3. The measured chrome is preserved: item height 57px (58px on the last, which
   also carries `border-bottom`), separators `#808080` via `border-top`, label
   `line-height: 24px` + `padding: 4px 0` with `box-sizing: content-box`,
   button `padding: 12px 16px` / height 56.

**Verified:** `dynamic-check.mjs` asserts 4 accordion items, panel content,
open/close and `aria-expanded` at 360. Pixel gate 0.00% at 360.

**Advisory delta — panel borrowing.** The accordion panel *contents* were never
captured (live lazy-loads them; the capture has headers only). Rather than
invent copy, each accordion item **borrows** its matching desktop column's nodes
at mobile and hands them back at desktop (`movePanels()`), so exactly one copy
of every link exists in the DOM at any width. The open-state CSS is likewise a
minimal reconstruction, invisible to the gate's closed default state.

## D7 — Analytics + tag manager

1. Provision a **new** container on the target property. Never copy NAB's
   container IDs or inline bootstrap.
2. The trailing tracking-pixel line box contributes 24px to `docHeight` 8692.
   Whatever replaces it must occupy the same box, or set the height delta
   expectation accordingly before re-running the gate.

**Status during the lift:** no tracking markup was copied. The 24px line box is
reproduced as a pure `body::after { display: block; height: 24px; content: '' }`
spacer in `styles/styles.css`. When a real container lands at rollout, **remove
that spacer** if the new tag occupies its own box, and re-run the gate.

**Verify:** `pixel-compare` height delta stays 0 at 360; if it moves, adjust
`.nab-footer__legal` padding-bottom (the gated value is `16px 0 160px`).
